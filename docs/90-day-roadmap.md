# 90-Day Legitimate Roadmap — ReproTriage

Goal at day 90: a real tool with real external users and a public maintenance record. That is the *start* of eligibility evidence for Codex for Open Source, not eligibility itself. Realistic window to look like accepted projects: 6-12+ months.

## Days 1-14 — Problem proof + v0 (DONE: this scaffold)
- [x] Deterministic checks, tests, README, MIT license
- [ ] Interview 10-15 maintainers, record their triage steps
- [ ] Recruit 3-5 design-partner repos (only maintainers who ask)
- [ ] Create public GitHub repo, push this code, tag v0.1.0
- Content: launch thread on X/LinkedIn + 60-sec demo

## Days 15-30 — v1 + first strangers
- Wire the comment-posting step in the Action, publish to GitHub Marketplace
- Optional LLM layer (BYO OpenAI key): label classification, missing-info draft, PR brief
- Submit to awesome-actions lists, write a dev.to build post
- Targets (planning aids, NOT program thresholds): 5-10 external repos installed, 3+ issues from strangers, 2 releases

## Days 31-60 — Reproduction module + proof
- Repro completeness scoring, then opt-in repro-run in adopter's own Actions sandbox with evidence log
- Publish case study with design partners: time-to-first-triage before/after
- Open 5-8 good first issues, mentor first contributors, reply to every issue/PR within 48h — this IS the maintenance evidence OpenAI looks for

## Days 61-90 — Harden + decide
- v2: repro-run GA (opt-in), docs, SECURITY.md, permissions audit
- Write "90 days of maintaining" retrospective with real numbers
- Decision point: apply to Codex for OSS ONLY if you can truthfully show meaningful usage, active maintenance, and a concrete API-credit plan. If evidence is thin, keep building to month 6-12. Review is rolling — there is no deadline to rush.

## Never do
Buy stars, star exchanges, alt accounts, bot traffic. OpenAI's Terms allow revocation for false/misleading info and multiple identities — and a reviewer can spot empty engagement in one click.
